# Screwdriver v1.2.0

Screwdriver v1.2 expands the inspection workflow from system discovery into evidence-grounded issue finding and agentic diagnostics while keeping the deterministic local inspection as the source of truth.

## Highlights

- Added `--find-issues` for focused fault discovery and diagnosis.
- Added the **Agentic System Diagnostic Report** alongside the **Agentic System Blueprint Report**.
- Agentic inspection now preserves deterministic findings and uses model reasoning to deepen diagnosis rather than replace observed evidence.
- Reworked the Blueprint's **Whole System Summary** to explain what kind of robotics system is running, how capable the machine is for that workload, available headroom, and likely bottlenecks.
- Improved hardware reporting with actual **Driver Bound** information.
- Strengthened cross-layer integration reasoning across physical hardware, drivers, OS interfaces, runtime owners, and endpoints/consumers.
- Added **Incomplete Integration Paths** so missing runtime owners or consumers are reported separately from real faults.
- Redesigned diagnostics around a complete list of prioritized real problems and concise, fix-oriented RCA guidance.
- Diagnostic steps now favor exact passive commands, expected results, interpretation, next action, and direct recovery verification.
- Hardened the finding pipeline so deterministic warnings and errors cannot be silently downgraded or removed by the agentic layer.
- Improved handling of ROS 2 environment and inspection-context problems without incorrectly claiming that the deployed ROS runtime is down.
- Prevented collector/normalization anomalies from being presented as robot failures unless raw evidence supports the diagnosis.
- Preserved the read-only safety boundary: Screwdriver does not automatically apply model-generated repairs or modify robot state.
- Improved local/SSH report handling and retained the deterministic local reports as the evidence foundation for agentic analysis.
- Expanded automated regression coverage for local inspection, agentic reporting, provider behavior, evidence validation, diagnostics, and SSH workflows.

## Report Model

Screwdriver now separates three engineering views:

- **Deterministic Local Report** — what the system actually exposes to passive inspection.
- **Agentic System Blueprint Report** — how the robot fits together, what kind of system it is running, and how the hardware/software layers connect.
- **Agentic System Diagnostic Report** — what is actually wrong, how to investigate or fix it, and how to verify recovery.

## Safety

Screwdriver remains passive by default. It does not automatically activate hardware, change configuration, restart services, modify permissions, flash firmware, or execute model-generated repair commands.

## Upgrade

Install the v1.2.0 wheel in an isolated Python environment using the normal Screwdriver packaging workflow. Existing provider configuration continues to use the supported OpenAI or Anthropic environment variables.
