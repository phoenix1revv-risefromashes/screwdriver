# Screwdriver v0.1.0 Specification

## Product promise

Run:

```bash
screwdriver inspect
```

and receive an evidence-backed profile of the Linux computer controlling the robot.

## Feature scope

Screwdriver `v0.1.0` will identify:

- Linux distribution and version
- Kernel release
- CPU architecture
- Computer or development-board model
- CPU and GPU
- Memory and storage
- Jetson, Raspberry Pi, x86 or generic Linux platform
- Container or virtual-machine environment
- Available system commands
- Readable `/proc`, `/sys` and `/dev` paths
- USB, PCIe, CAN, I2C, SPI and GPIO controllers
- ROS 2 installation and distribution
- JetPack, L4T and CUDA on Jetson systems

## Inspection flow

1. Run a deterministic capability probe.
2. Detect the platform and available capabilities.
3. Create a capability manifest.
4. Let the agent select registered scanners.
5. Run compatible read-only scanners.
6. Collect evidence.
7. Produce terminal and JSON reports.

## Agent restrictions

The agent may:

- Read the capability manifest
- Select registered scanners
- Request safe follow-up scans
- Stop when sufficient evidence exists
- Explain collected results

The agent may not:

- Generate arbitrary shell commands
- Use `sudo`
- Modify the operating system
- Install packages
- Access actuators
- Guess unsupported facts

## Required commands

```bash
screwdriver inspect
screwdriver inspect --json
screwdriver inspect --no-ai
```

## Scanner result states

Every scanner must return one of these states:

- `SUPPORTED`
- `UNAVAILABLE`
- `UNSUPPORTED`
- `FAILED`

A missing command, unreadable path or unsupported platform must not crash the application.

## Evidence requirements

Every reported fact must include:

- Field name
- Collected value
- Evidence source
- Scanner name
- Collection status
- Identification confidence

Unknown facts must remain `UNKNOWN`.

## Acceptance criteria

The release is complete when:

- Host identification works end to end
- Jetson, Raspberry Pi, x86 and generic Linux fixtures pass
- Missing commands do not crash the application
- Deterministic inspection works without AI
- The agent uses only registered scanners
- Terminal and JSON reports contain the same facts
- All inspection operations remain read-only
- Tests, linting and package building pass
- GitHub Actions passes
